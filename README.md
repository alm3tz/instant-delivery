# توصيل فوري

نسخة تطوير أولية لتجربة رحلة التوصيل في تطبيق Expo للآيفون والأندرويد. يعمل الخادم محليًا ويحفظ الطلبات والمحافظ في SQLite.

## تشغيل الخادم

من مجلد المشروع، شغّل الأوامر التالية باستخدام Node.js 24.

```powershell
node --test server/flow.test.mjs
node server/index.mjs
```

يستمع الخادم افتراضيًا على `127.0.0.1:4100`. لتجربة هاتف على شبكة محلية خاصة، اضبط `DELIVERY_DEMO_HOST` إلى `0.0.0.0` وأعد تشغيل الخادم، ثم اضبط عنوانه في تطبيق الجوال على عنوان الحاسوب في الشبكة. الحسابات الموجودة في التطبيق تجريبية ومعروفة، لذا استخدم الخادم داخل بيئة اختبار فقط.

## تشغيل الجوال

يتطلب الطرف الخاص بالجوال npm وبيئة جهاز أو محاكي تدعم Expo SDK 56. اضبط `EXPO_PUBLIC_API_URL` قبل بدء Expo عند استخدام هاتف فعلي. العنوان الافتراضي لمحاكي Android هو `http://10.0.2.2:4100` ولمحاكي iOS هو `http://127.0.0.1:4100`.

```powershell
cd mobile
npm install
npx expo install --fix
npm start
```

## تجربة رحلة

1. في واجهة المحل، أدخل وصف الوجهة وإحداثياتها. مثال للتجربة في عمّان هو خط عرض `31.951` وخط طول `35.928`.
2. انتقل إلى حساب السائق واضغط **تحديث الموقع والتوفّر**. عند ترك الإحداثيات فارغة يستخدم التطبيق موقع السائق المحفوظ. يبقى الموقع صالحًا للمطابقة لمدة دقيقتين.
3. اقبل الطلب وتحقق من حجز 250 فلسًا. حدّث الحالة إلى **وصلت إلى المحل** ثم **استلمت الطلب** ثم **تم التسليم**.
4. من الإدارة، سجّل شحنًا للسائق بالفلس. يظهر المبلغ في الرصيد المتاح بعد تأكيده في واجهة السائق.

الدفع النقدي وأجرة التوصيل تتم خارج التطبيق. الواجهة تعرض معاملات محفظة العمولة فقط.

## حدود هذه النسخة

- تتضمن البيانات التجريبية متجرًا واحدًا وسائقين اثنين، وتوجد شاشة الإدارة داخل تطبيق الاختبار.
- إدخال الإحداثيات يدوي، وروابط المواقع تفتح تطبيق الخرائط. اختيار دبوس الوجهة، وموقع GPS الفعلي، والخريطة الموحّدة للإدارة أجزاء متبقية.
- وقت الوصول المعروض تقديري من المسافة بخط مستقيم. حسابه حسب مسار القيادة، والإشعارات، وتسلسل البحث بحسب القرب، وانتهاء البحث عند غياب سائق مؤهل أجزاء متبقية.
- تسجيل الدخول الفعلي، وتسجيل المتاجر والسائقين، وتجهيز نسخة متجر التطبيقات أجزاء متبقية.
